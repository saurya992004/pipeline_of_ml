# AIOps Setup & Run Guide — Kafka + Airflow

This guide is organized by **where you are running the project**.

## Quick decision table

| Environment | Kafka | Airflow | Commands |
|---|---|---|---|
| GitHub Codespaces | Linux / `.sh` | Linux / `.sh` | Use Codespaces section |
| Windows + VS Code | PowerShell / `.bat` | WSL / Ubuntu | Use Desktop section |
| WSL / Ubuntu | `.sh` | `.sh` | Use WSL sections |

# PART 1 — GITHUB CODESPACES

Codespaces uses Linux commands.

## A. Kafka in Codespaces

### A1. Install Kafka — ONE TIME ONLY

```bash
cd ~

wget https://downloads.apache.org/kafka/4.0.1/kafka_2.13-4.0.1.tgz

tar -xzf kafka_2.13-4.0.1.tgz

mv kafka_2.13-4.0.1 kafka

cd ~/kafka
```

Check:

```bash
bin/kafka-topics.sh --version
```

You only need to download/extract Kafka once.

---

## A2. Initialize Kafka storage — FIRST INSTALLATION ONLY

Do NOT repeat the `format` command every time you start Kafka.

Open **Terminal 1**:

```bash
cd ~/kafka

export KAFKA_HEAP_OPTS="-Xmx1G -Xms512M"

KAFKA_CLUSTER_ID=$(bin/kafka-storage.sh random-uuid)

echo $KAFKA_CLUSTER_ID
```

Now format the fresh installation:

```bash
bin/kafka-storage.sh format   -t "$KAFKA_CLUSTER_ID"   -c config/server.properties   --standalone
```

After this succeeds, the storage is initialized.

---

## A3. Start Kafka — EVERY TIME YOU NEED KAFKA

**Terminal 1:**

```bash
cd ~/kafka

export KAFKA_HEAP_OPTS="-Xmx1G -Xms512M"

bin/kafka-server-start.sh config/server.properties
```

Keep this terminal running.

Do NOT close it while your producer/consumer programs are running.

---

## A4. Create the Kafka topic — ONCE PER NEW TOPIC

Open **Terminal 2**:

```bash
cd ~/kafka

bin/kafka-topics.sh   --bootstrap-server localhost:9092   --create   --topic server_metrics   --partitions 1   --replication-factor 1
```

Check that it exists:

```bash
bin/kafka-topics.sh   --bootstrap-server localhost:9092   --list
```

You should see:

```text
server_metrics
```

### If the topic already exists

Do NOT create it again. Just run:

```bash
bin/kafka-topics.sh   --bootstrap-server localhost:9092   --list
```

---

## A5. Optional: Console Producer/Consumer

These are only for **manual testing**. You do NOT need them when using Python producer/consumer files.

### Console Producer — Terminal 2

```bash
cd ~/kafka

bin/kafka-console-producer.sh   --bootstrap-server localhost:9092   --topic server_metrics
```

Type messages such as:

```text
CPU=50
RAM=60
```

### Console Consumer — Terminal 3

```bash
cd ~/kafka

bin/kafka-console-consumer.sh   --bootstrap-server localhost:9092   --topic server_metrics   --from-beginning
```

You should see the messages from the producer.

---

## A6. Python Kafka Producer/Consumer — NORMAL PROJECT WORKFLOW

Install the Python library:

```bash
pip install kafka-python
```

Usually install this once in your Python environment.

### Start Kafka first

**Terminal 1:**

```bash
cd ~/kafka
bin/kafka-server-start.sh config/server.properties
```

### Then run Python producer

**Terminal 2:**

```bash
python q2/producer.py
```

### Then run Python consumer

**Terminal 3:**

```bash
python q3/consumer.py
```

Normal flow:

```text
Kafka Broker
     ↓
server_metrics topic
     ↓
Python Producer → Kafka → Python Consumer
```

You do NOT need the console producer/consumer when the Python files are being used.

# PART 2 — AIRFLOW IN GITHUB CODESPACES

Airflow should use its own Python virtual environment.

## B1. Create the environment — ONE TIME

Replace `YOUR-REPO` with your repository name.

```bash
cd /workspaces/YOUR-REPO

python3 -m venv airflow-venv

source airflow-venv/bin/activate
```

You should see:

```text
(airflow-venv)
```

at the beginning of the terminal prompt.

---

## B2. Install Airflow

With the virtual environment activated:

```bash
pip install --upgrade pip
pip install apache-airflow
```

Check:

```bash
airflow version
```

---

## B3. Start Airflow

```bash
airflow standalone
```

Keep this terminal running.

---

## B4. Open a NEW terminal

In the new terminal:

```bash
cd /workspaces/YOUR-REPO
source airflow-venv/bin/activate
```

Every new terminal that you use for Airflow must activate the environment.

---

## B5. Find the DAG folder

```bash
airflow config get-value core dags_folder
```

---

## B6. Check DAGs

```bash
airflow dags list
```

Check import errors:

```bash
airflow dags list-import-errors
```

---

## B7. Check Python syntax

For this DAG:

```bash
python -m py_compile dags/aiops_workflow.py
```

No output normally means the syntax check passed.

---

## B8. Test a task

Example:

```bash
airflow tasks test aiops_workflow collect_metrics 2026-09-20
```

Use the required execution date for your assignment.

---

## B9. Trigger the DAG

```bash
airflow dags trigger aiops_workflow
```

---

## B10. Open Airflow UI

In Codespaces:

```text
PORTS → port 8080 → Open in Browser
```

## C4. Initialize Kafka storage — FIRST INSTALLATION ONLY

**PowerShell 1:**




Keep this PowerShell window running.

# MOST IMPORTANT: WHAT TO RUN WHEN?

## First-ever Kafka setup

```text
Install Java
    ↓
Download Kafka
    ↓
Extract Kafka
    ↓
Format Kafka storage
    ↓
Create topic
```

The storage `format` step is **NOT an every-run command**.

---

## Every time you want to use Kafka

```text
START KAFKA BROKER
       ↓
Make sure topic exists
       ↓
Run producer
       ↓
Run consumer
```

### Linux

```bash
# Terminal 1
cd ~/kafka
bin/kafka-server-start.sh config/server.properties

# Terminal 2
python q2/producer.py

# Terminal 3
python q3/consumer.py
```

### Windows

```powershell
# PowerShell 1
cd C:\kafka
.in\windows\kafka-server-start.bat .\config\server.properties

# PowerShell 2
python q2\producer.py

# PowerShell 3
python q3\consumer.py
```

---

# Console vs Python

Use **console producer/consumer only when you want to manually test Kafka**.

For your actual Python project:

```text
❌ Console Producer
❌ Console Consumer

✅ Python Producer
✅ Python Consumer
```

Kafka broker is still required:

```text
                 KAFKA BROKER
                      │
                server_metrics
                 /                          ↓            ↓
       Python Producer   Python Consumer
```

# Final Environment Map

```text
┌─────────────────────────────┐
│     GITHUB CODESPACES       │
│                             │
│ Kafka  → Linux .sh          │
│ Airflow → Linux             │
└─────────────────────────────┘


┌─────────────────────────────┐
│      WINDOWS DESKTOP        │
│                             │
│ Kafka → PowerShell .bat     │
│                             │
│ Airflow → WSL/Ubuntu .sh    │
└─────────────────────────────┘
```

## Golden rules

1. **Kafka broker must be running before producer/consumer.**
2. **Format Kafka storage only on a fresh installation.**
3. **Create a topic only if it doesn't already exist.**
4. **Console producer/consumer are optional testing tools.**
5. **Use Python producer/consumer for your actual application.**
6. **Keep the Kafka terminal running while using Kafka.**
7. **Airflow uses its own virtual environment.**
8. **Activate the Airflow virtual environment in every new terminal.**
9. **Codespaces uses Linux `.sh` commands.**
10. **Windows Kafka uses PowerShell `.bat`; WSL Airflow uses Linux commands.**
11. **Commit and push only after the work is complete.**
